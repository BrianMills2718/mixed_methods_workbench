## 2026-07-12 — mixed_methods_workbench DEMO-C1 — missing-negative-control / structural tests overstated semantic closure

**Declared:** DEMO-C1 passed its local positive/negative controls, strict typing,
Ruff, `make check`, and clean-clone execution and was documented as earning
eight A/test synthetic contract rows.

**Audit found:** Held-out mutations passed same-length shifted offsets,
duplicate-but-set-complete PT rankings, duplicate PT evidence references,
same-method/ambiguous object links, and appended claim-limit escalations. Open
QC/PT/GT/link prose also evaded finite semantic blacklists, while the coverage
language implied that the program had validated its methodological meaning.
The documented `make demo-coverage` surface was absent and the CLI failure path
had not been executed as a subprocess.

**Verification gap:** Self-review used one positive fixture and negative
controls that changed obvious fields/phrases. It did not run a field-semantics
matrix (identity, cardinality, uniqueness, cross-object compatibility,
closed-envelope escalation), an equivalent-value held-out set, or the actual
invalid CLI boundary. Most importantly, it treated regex rejection over open
prose as semantic validation rather than acknowledging that the prose had no
programmatic authority.

**General failure mode:** missing-negative-control / structural tests overstated
semantic closure — schema and example-string controls can prove structure but
cannot license the meaning of arbitrary prose; set equality can also conceal
duplicate cardinality and method-only IDs can conceal object-kind ambiguity.

**Prevention:** Before promoting a typed contract, inventory every claimed
field semantic and test identity, cardinality, uniqueness, compatibility,
closed-envelope escalation, and equivalent held-outs. Open prose must either
be converted to typed authoritative fields or carry an explicit
non-authoritative/human-review status; never claim regexes establish semantic
method fidelity. Exercise the real CLI/Make failure surface, not only the model
validator. This recurs in the shared missing-negative-control and partial-scope
corpus, so no duplicate policy proposal is recommended.
