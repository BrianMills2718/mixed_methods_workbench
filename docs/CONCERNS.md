# Mixed Methods Workbench Concern Register

Each concern must be dispositioned at slice boundaries: `open`, `resolved`,
`mitigated`, `accepted`, `deferred`, or `escalated`.

| ID | Status | Concern | Why It Matters | Disposition |
|---|---|---|---|---|
| C001 | open | Shared evidence contract may be too weak to represent both QC anchors and PT evidence likelihoods. | A bad seam would force lossy adapters or premature schema churn. | Resolve in Slice 1 by building a fixture-backed contract mockup and adapter readout. |
| C002 | open | The workbench could blur estimands: qualitative claim support, process-tracing comparative support, and cross-case causal effects are different. | False precision would damage the product's methodology claims. | Require method-specific `estimand_kind` and report caveats in every synthesis payload. |
| C003 | open | UI shell could become a superficial dashboard over unrelated artifacts. | The product goal is a research workflow, not a portfolio index. | First mockup must show a concrete data-to-claim-to-hypothesis-to-report path. |
| C004 | open | Cross-repo imports can create dependency cycles or brittle local path coupling. | The workbench needs durable module boundaries. | Use file/artifact adapters first; defer direct library imports until contracts stabilize. |
| C005 | open | "PhD-level research output" is an ambition, not a single deterministic acceptance test. | The plan must not fake a universal quality threshold. | Treat quality as a ladder: structural gates now, expert/frozen-case validation later. |
| C006 | open | The engine repos are not all stable enough to build the workbench against yet. | A workbench slice would either depend on dirty/untracked state or undocumented export gaps. | Execute Plan 002 readiness gates before Plan 001. |
| C007 | open | Theory Forge is not represented in the original QC/PT architecture. | Bolting it on later could confuse generated theory, theory operationalization, and compiled analysis code. | Treat Theory Forge as a dependency subplan and add only a `TheoryOperationalizationArtifact` after a real fixture. |
| C008 | open | AC14/AC15 Theory Forge benchmark evidence could be misused as mixed-methods evidence. | Those benchmarks measure coding-agent/codegen behavior, not qualitative/process-tracing integration utility. | Keep AC15 optional and out of the workbench critical path. |
| C009 | open | `process_tracing` needs a stable export seam before the workbench consumes it. | Parsing `result.json` or importing `pt.schemas` would couple the workbench to internal PT artifacts. | Require `pt_export_v1` before PT adapters. |
| C010 | open | `process_tracing/workbench/frontend/node_modules/` is untracked. | Repo-readiness checks remain dirty and plans could mistake generated dependencies for durable source. | Ignore/remove it or record an explicit disposition before export work. |
| C011 | mitigated | The earlier `qualitative_coding` dirty-worktree claim is stale; its main checkout was clean on 2026-07-09. | Historical readiness docs can drift from live state. | Plan 003 requires a generated readiness manifest at point of use; do not reuse Plan 002 status as live evidence. |
| C012 | open | Theory Forge current health and v14/v15 status are uncertain. | A theory export contract built on stale schema assumptions would churn quickly. | Run a dedicated Theory Forge readiness investigation before adding a workbench theory contract. |
| C013 | mitigated | Synthetic workbench fixtures could be mistaken for engine readiness evidence. | Placeholder JSON can look like a real integrated payload. | Coverage now grades the synthetic seam C and the incomplete inventory F; real fixtures still require engine-local validation. |
| C014 | open | The original semantic negative controls failed on stale manifest hashes before reaching their intended invariants. | “Any failure is success” made the gate non-discriminating and supported false A grades. | Hash-neutral controls now assert expected diagnostics; add remaining schema/category controls before closing version 0.0. |
| C015 | open | Most readiness rows remain doc-only and the inventory row is missing required provenance. | The workbench could move to UI/adapters before real fixtures license those claims. | The corrected report is 0 A, 0 B, 2 C, 5 D, 1 F; close the F row before enforcement. |
| C016 | open | The initial QC/PT slice was described as mixed-methods synthesis even though it has no quantitative strand. | The label would overclaim the methodology and conceal the main missing capability. | Version 0.1 is now explicitly multi-method qualitative; only version 0.4 may claim mixed methods after qual-quant integration. |
| C017 | open | Theory operationalization was modeled as an `EvidenceRecord` supporting an assertion. | A generated theory object is context or a test obligation, not empirical support. | Contract/fixture prose is corrected and targeted controls reject theory-as-evidence/assertion; version 0.0 still needs typed schemas. |
| C018 | open | Quantitative text analysis has no engine or adapter owner. | The first genuine mixed-methods slice cannot exist without a validated quantitative strand. | Before version 0.4, select one task/design and established libraries, assign an owner, and extract shared infrastructure only after a second real slice. |
| C019 | open | A universal qualitative workflow would impose the wrong validity rules on some traditions. | Reflexive TA, codebook analysis, grounded theory, discourse analysis, and other traditions do not share one review or reliability regime. | Introduce versioned method profiles with workflow, quality, forbidden-claim, and reporting obligations. |
| C020 | open | `research_v3` docs conflict over whether the project is active or archived. | Duplicate ownership of deep research/retrieval could create another unstable dependency. | Keep it off the critical path; resolve by ADR before integration. |
| C021 | open | Cross-repo product releases and producer schema versions can drift independently. | A green engine may still be incompatible with a workbench release. | Maintain semantic artifact versions, supported-major ranges, and a pinned compatibility/readiness manifest. |
| C022 | open | Privacy, consent, licensing, translation, and source-use constraints are not first-class in the domain. | Real research corpora can be unethical or unlawful to send to models or publish even when analysis is technically correct. | Add governance metadata at version 0.1 and harden access/de-identification/retention profiles by version 0.7. |
| C023 | open | Grounded Research is mechanically mature but its general methodological validity is not established. | Treating its current benchmarks as universal would turn adjudication into an unearned truth oracle. | Integrate through contested-claim artifacts in 0.2 and evaluate on workbench cases with human dispositions. |
| C024 | open | Joint displays and meta-inference are absent. | Co-locating outputs is not mixed-methods integration. | Version 0.4 requires an explicit integration operation, joint display, strand-relationship classification, contradiction disposition, and meta-inference. |
| C025 | open | Current validator logic is ad hoc rather than generated from typed producer/consumer models. | Recursive key checks cannot establish complete contract coverage or version compatibility. | Replace it in version 0.0 with Pydantic/JSON Schema producer and consumer contracts plus snapshots and controls. |
| C026 | open | SOTA ambition lacks an independent, multi-domain comparative benchmark. | Feature breadth and plausible outputs do not establish research quality or advantage. | Version 0.8 requires frozen/held-out cases, experts, planted failures, trace evaluation, incumbent baselines, ablations, and observed cost/time. |
